# Hospital Workflow Simulation Module (Phase 3.1)

## 1. Purpose of the Simulator
The Hospital Workflow Simulation Module is an isolated sub-system built inside the Hospital Management System root. It provides a safe, transaction-controlled foundation for generating synthetic patient telemetry and workflow data for AI-HODE model training without compromising real hospital database integrity or triggering external side effects.

## 2. Location of the Module
- **Module Path**: `<PROJECT_ROOT>/simulation/` (e.g., `C:/xampp/htdocs/Hospital_Project/simulation/`)
- **Web URL**: `http://localhost/Hospital_Project/simulation/`

## 4. How Simulation Safety Works
When a simulation is executed, `SimulationSafetyService` enables safety mode (`SIMULATION_MODE=true`):
- **Email Protection**: Real email dispatch via `EmailHelper` / Resend API is intercepted and written to local simulation logs.
- **Payment Protection**: Live Razorpay API calls and checkout forms via `RazorpayHelper` are bypassed and mocked.
- **Database Safety**: All operations run within NeonDB PostgreSQL transaction blocks (`BEGIN` ... `ROLLBACK`).

## 5. Environment & `SIMULATION_MODE`
`SIMULATION_MODE` is **OFF by default** (`false`). The normal hospital management system (Admin, Doctor, Patient portals) functions normally without simulation overhead. Simulation is explicitly engaged only through the simulation module controls.

## 6. How Dry Run Works (`RUN DRY TEST`)
Executing `RUN DRY TEST` performs an end-to-end verification:
1. Generates a unique run ID (e.g., `SIM-DRY-20260817-220000`).
2. Activates the safety layer.
3. Tests database transaction begin, write, and rollback capabilities.
4. Verifies presence of required schema tables and side-effect guards.
5. Updates simulation run status to `COMPLETED`.
6. Leaves **ZERO transient residue** in the main hospital tables.

## 7. How Future Simulation Will Work (Phase 3.2+)
In upcoming phases, `HospitalWorkflowEngine` will generate multi-day OPD and IPD journeys, creating realistic queue events, doctor workloads, and diagnostic records to train the AI-HODE engine.

## 8. Resetting a Simulation Run
To reset data generated by a specific simulation run:
1. Access `http://localhost/Hospital_Project/simulation/reset_simulation.php`.
2. Select the target `SIM-XXXXXXXX` run ID to preview recorded events.
3. Confirm reset. The cleanup service deletes associated event metadata within a database transaction. Real hospital records are **never** modified or deleted.

## 9. Warning on Shared/Production Databases
> [!CAUTION]
> Always verify that `SIMULATION_MODE` safety protection is active before running multi-day simulation routines on shared production environments.
